# 💧 상수도 관망 압력 관제 데모

실제 장비 없이 **가짜 센서 데이터**로 동작하는 상수도 관망 압력 관제 화면입니다.
면접 시연·연습용이며, 화면의 값은 모두 임의로 만든 것입니다.

- 압력 센서 6개 (경기도 부천시 일대, 위치는 임의 지정)
- 1초마다 압력 측정 → SQLite DB 파일 하나(`water_demo.db`)에 저장
- 수충격·통신 두절·저장 후 전송·중복 데이터를 흉내 내고, 관제 화면에서 실시간으로 확인

---

## 1. 설치

1. **파이썬 3.11 이상** 설치: <https://www.python.org/downloads/>
   - 설치 첫 화면에서 **"Add python.exe to PATH"를 꼭 체크**하세요.
2. 이 폴더를 원하는 곳에 둡니다. (예: `C:\water_demo`)

`run.bat`으로 실행하면 처음 한 번 필요한 패키지가 **자동으로 설치**됩니다. (인터넷 연결 필요, 몇 분 소요)

직접 설치하려면 이 폴더에서 명령 프롬프트를 열고:

```bat
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

## 2. 실행

### 방법 A. 더블클릭 (가장 쉬움)

`run.bat`을 더블클릭하면

1. (처음 한 번) 가상환경을 만들고 패키지를 설치하고
2. **시뮬레이터**가 새 검은 창에서 켜지고 (DB가 없으면 지난 30분 데이터를 먼저 채움)
3. **관제 화면**이 켜지면서 몇 초 뒤 브라우저에 `http://localhost:8501` 이 열립니다.

끌 때는 관제 화면 창에서 `Ctrl + C` → 시뮬레이터도 같이 꺼집니다.
(창을 X로 닫았다면 시뮬레이터 창도 따로 닫아 주세요.)

### 방법 B. 화면만 켜기

```bat
.venv\Scripts\activate
streamlit run app.py
```

따로 켜진 시뮬레이터가 없으면 **화면 안에서 시뮬레이터가 자동으로 함께 돕니다.** (처음이면 지난 30분 데이터도 채움)
인터넷에 배포했을 때도 이 방식으로 동작합니다.

### 방법 C. 시뮬레이터와 화면을 각각 켜기

시뮬레이터 진행 상황을 검은 창에서 보고 싶을 때 씁니다. 명령 프롬프트 창 **두 개**를 열고, 둘 다 이 폴더에서 `.venv\Scripts\activate` 를 먼저 실행합니다.
**시뮬레이터를 먼저** 켜야 화면이 시뮬레이터를 또 켜지 않습니다. (두 개가 동시에 돌려고 하면 나중 것이 스스로 종료됨)

**창 1 — 시뮬레이터**

```bat
python simulator.py
```

| 옵션 | 뜻 |
|---|---|
| `--backfill 30` | 지난 30분 데이터를 먼저 빠르게 채운 뒤 실시간 실행 (기록 조회 시연용) |
| `--reset` | 기존 DB를 지우고 새로 시작 |
| `--seconds 60` | 60초만 실행하고 종료 |

**창 2 — 관제 화면**

```bat
streamlit run app.py
```

브라우저에서 <http://localhost:8501> 을 엽니다.

> 면접 전에 `python simulator.py --reset --backfill 60` 으로 시작하면 깨끗한 1시간치 기록과 함께 시연할 수 있습니다.

## 3. 인터넷에 올려서 외부에서 보기 (Streamlit Community Cloud, 무료)

`https://○○○.streamlit.app` 같은 주소가 생겨 면접관이 휴대폰·다른 PC에서 바로 볼 수 있습니다.

**① GitHub에 코드 올리기**
1. <https://github.com> 에 가입·로그인 → 오른쪽 위 **+** → **New repository**
2. 이름 입력 (예: `water-pressure-demo`) → **Public** 선택 → **Create repository**
3. 새 저장소 화면에서 **uploading an existing file** 링크 클릭
4. 이 폴더의 파일을 끌어다 놓기: `app.py`, `simulator.py`, `config.py`, `rules.py`, `db.py`, `requirements.txt`, `README.md`, `.gitignore`
   - `.venv` 폴더와 `water_demo.db` 파일은 **올리지 마세요.**
   - `run.bat`, `launcher.py` 는 올려도 되고 안 올려도 됩니다.
5. **Commit changes** 클릭
6. `.streamlit` 폴더도 올립니다: **Add file → Create new file** → 이름 칸에 `.streamlit/config.toml` 입력 → 이 폴더의 `.streamlit\config.toml` 내용을 메모장으로 열어 복사·붙여넣기 → **Commit changes**
   (`.`으로 시작하는 폴더는 끌어다 놓기로 안 올라가는 경우가 있어서 이렇게 따로 만듭니다)

**② Streamlit Cloud에 배포**
1. <https://share.streamlit.io> 접속 → **Continue with GitHub** 로 로그인 → GitHub 접근 허용
2. **Create app** → **Deploy a public app from GitHub**
3. Repository: 방금 만든 저장소, Branch: `main`, Main file path: `app.py`
4. **App URL** 에 원하는 주소 입력 (예: `water-pressure-demo`)
5. **Advanced settings** → Python version **3.12** 선택
6. **Deploy** → 1~3분 기다리면 화면이 뜹니다.

**알아 둘 점**
- 인터넷 서버에서는 화면 안에서 시뮬레이터가 함께 돕니다. 시간은 한국 시각으로 표시됩니다.
- 12시간 동안 아무도 접속하지 않으면 앱이 잠듭니다. 면접 전에 한 번 열어서 깨워 두세요. (깨우는 데 30초~1분)
- 서버가 다시 시작되면 데이터가 지워지고 지난 30분 데이터부터 새로 채워집니다.
- 코드를 고친 뒤 GitHub에 다시 올리면 몇 분 안에 자동으로 반영됩니다.
- 누구나 주소로 들어와 **시연 도구** 버튼을 누를 수 있습니다. (데모라 문제는 없음)

## 4. 화면 설명

| 영역 | 내용 |
|---|---|
| **상태 카드** (맨 위) | 전체 센서 수, 🟢 정상 / 🔴 경고 / ⚪ 통신 두절 센서 수 |
| **센서 위치 지도** | 센서를 점으로 표시. 초록 = 정상, 빨강 = 압력 이상, 회색 = 통신 두절. 점에 마우스를 올리면 이름·압력·상태가 보임 |
| **센서 상태 표** | 센서별 최근 압력, 마지막 수신 시각, 경고 이유 |
| **실시간 압력 그래프** | 센서를 고르면 최근 5분 그래프. 초록 배경 = 정상 범위, 빨간 점 = 이상 값, 선이 끊긴 곳 = 데이터 없음, 회색 영역 = 지금 통신 두절 중 |
| **알림 목록** | 압력 이상 🔴 / 수충격 의심 🟠 / 통신 두절 ⚪ / 통신 복구 🔵 를 최신순으로 표시 |
| **기록 조회** | 날짜·시간 범위와 센서를 골라 지난 그래프 다시 보기. 센서별 평균·최소·최대·수신율, 그 기간의 알림, CSV 내려받기 |
| **왼쪽 메뉴 – 시연 도구** | 고른 센서에 바로 **수충격 일으키기 / 통신 끊기**. 무작위 상황을 기다리지 않고 시연할 때 사용 |
| **맨 아래** | "연습용 데모이며 실제 데이터가 아닙니다" 안내 |

위쪽 실시간 영역은 **3초마다 자동 새로고침**되고, 기록 조회 영역은 [조회] 버튼을 누를 때만 바뀝니다.

## 5. 이상 판단 규칙 (`config.py` 에서 변경)

| 규칙 | 기본값 | 설정 이름 |
|---|---|---|
| 압력 이상: 정상 범위를 벗어남 | 2.5 ~ 5.5 kgf/cm² | `NORMAL_MIN`, `NORMAL_MAX` |
| 수충격 의심: 1초 사이 큰 변화 | 1.0 이상 | `HAMMER_DELTA` |
| 통신 두절: 마지막 수신 후 경과 | 20초 초과 | `COMM_TIMEOUT_SEC` |
| 화면 경고 유지 시간 | 15초 | `WARNING_HOLD_SEC` |
| 같은 알림 반복 방지 | 10초 | `ALERT_COOLDOWN_SEC` |
| 화면 새로고침 주기 | 3초 | `REFRESH_SEC` |

수충격·통신 두절이 일어나는 빈도, 장비 보관 한도 등 시뮬레이션 값도 같은 파일에 있습니다.
값을 바꾼 뒤에는 시뮬레이터와 화면을 다시 켜 주세요.

## 6. 동작 원리 (면접 설명용)

```
[가짜 현장 센서 6개] --1초마다--> [수집 서버: 저장 + 이상 판단] --> [SQLite DB] <-- [관제 화면 (Streamlit)]
        └─ simulator.py ───────────────────────────────┘                          └─ app.py
```

- **측정 시각과 수신 시각을 따로 저장**: 그래프는 센서가 잰 시각(`measured_at`), 통신 두절 판단은 서버가 받은 시각(`received_at`) 기준.
- **저장 후 전송(Store & Forward)**: 통신이 끊긴 동안 센서는 값을 장비 안에 보관하다가, 다시 연결되면 한꺼번에 보냅니다.
  장비 보관 한도(`DEVICE_BUFFER_SIZE`, 기본 40개)를 넘으면 오래된 값부터 사라져 그래프에 **빈 구간**이 남습니다.
- **중복 방지**: DB의 기본 키가 `(센서 ID, 측정 시각)` 이라 같은 데이터가 다시 와도 한 번만 저장됩니다(`INSERT OR IGNORE`).
  재연결 때 일부러 최근 데이터 5건을 다시 보내는데, 알림 목록의 "통신 복구" 내용에 중복 무시 건수가 나옵니다.
- **늦게 도착한 데이터도 판단**: 통신 복구 후 받은 과거 데이터에서도 압력 이상을 찾아 알림을 남깁니다.
  이때 알림 목록의 '서버 수신' 시각이 '발생 시각'보다 늦게 표시됩니다.
- **빈 구간 표시**: 3초 넘게 데이터가 없으면 그래프 선을 이어 붙이지 않고 끊어서 보여 줍니다.

## 7. 파일 구성

| 파일 | 역할 |
|---|---|
| `config.py` | 모든 설정값 (판단 기준, 센서 목록, 시뮬레이션 확률 등) |
| `simulator.py` | 가짜 센서 + 수집 서버 (저장·이상 판단·알림 기록) |
| `app.py` | 관제 화면 (Streamlit) |
| `rules.py` | 이상 판단 규칙 (시뮬레이터와 화면이 함께 사용) |
| `db.py` | SQLite 저장·조회 |
| `launcher.py` | run.bat 이 실행하는 한 번에 켜기 도우미 |
| `.streamlit/config.toml` | Streamlit 설정 |
| `.gitignore` | GitHub 에 올리지 않을 파일 목록 |
| `run.bat` | Windows 더블클릭 실행 파일 |
| `water_demo.db` | 실행하면 생기는 데이터 파일 (지우면 처음부터 다시 시작) |

## 8. 문제 해결

- **지도 배경이 안 보임**: 지도 바탕 그림은 인터넷에서 받아옵니다. 인터넷 연결을 확인하세요. (센서 점과 상태 표는 그대로 동작)
- **"최근 데이터가 없습니다" 경고**: 시뮬레이터 창이 켜져 있는지 확인하세요.
- **패키지 설치가 중간에 실패**: `.venv` 폴더를 지우고 `run.bat`을 다시 실행하세요.
- **처음부터 다시 하고 싶음**: 모두 끈 뒤 `water_demo.db`(와 `-wal`, `-shm` 파일)를 지우거나 `python simulator.py --reset`.
